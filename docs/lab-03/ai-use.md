# CPE 334 Lab 3 AI Usage Disclosure (`docs/lab-03/ai-use.md`)

## 1. AI Assistance Disclosure Summary

In accordance with course policies for CPE 334, this document discloses the extent and nature of AI assistance used during the planning, design, implementation, and testing of **Lab 3: Users, Roles, IT Staff Ticketing, and Admin Screens**.

* **AI Agent Model**: Antigravity (Google DeepMind pair programming assistant)
* **Primary Roles**: Architecture design, specification drafting, TDD test suite generation, server API implementation, React component creation, and regression verification.

---

## 2. Prompts & Interaction Workflows

### 2.1 Specification & Planning Phase
* **User Directive**: Analyze the official Lab 3 PDF handout and existing repository code. Formulate formal specifications for system architecture, authentication, server-side authorization matrix, UI views, and test traceability.
* **AI Output**: Created `docs/lab-03/specification.md`, `ui-spec.md`, `api-spec.md`, and `tests.md`.
* **Human Verification**: Verified that all business rules, authorization boundaries, password constraints, and ticket status transition matrices match the official PDF requirements without ambiguity.

### 2.2 Database & Data Evolution
* **User Directive**: Extend PostgreSQL/Prisma schema to add `User`, `PublicComment`, `InternalNote`, update `Ticket` relations and enums, and create an idempotent seed.
* **AI Output**: Updated `server/prisma/schema.prisma` and created `server/prisma/seed.ts`.
* **Human Verification**: Confirmed that Lab 2 Ticket and Attachment models/data remained fully compatible and intact.

### 2.3 Authentication & Server Authorization
* **User Directive**: Implement JWT authentication, bcrypt password hashing, mandatory first-login password change, and strict server-side role & ownership authorization middleware.
* **AI Output**: Created `utils/auth.ts`, `middleware/auth.ts`, and updated `server/src/app.ts`.
* **Human Verification**: Created automated tests (`auth.api.test.ts`, `authorization.api.test.ts`) ensuring identity comes strictly from server-side JWT session tokens and never client-supplied `requesterId` headers.

### 2.4 Staff Queue & Admin User Management Screens
* **User Directive**: Build IT Staff Queue, IT Staff Ticket Detail with Public Comments and Internal Notes, and Administrator User Management UI.
* **AI Output**: Created `PublicCommentsSection.tsx`, `InternalNotesSection.tsx`, `StaffTicketQueueView.tsx`, `StaffTicketDetailView.tsx`, and `UserManagementView.tsx`.
* **Human Verification**: Ran Vitest component unit tests and verified Zen Green aesthetic styling.

---

## 3. Human Oversight & Critical Decisions

1. **Client Identity Spoofing Mitigation**: The AI ensured that when `req.user` is present, `requesterId` is overridden with `req.user.id`, preventing identity spoofing.
2. **Administrator Safety Guards**: Verified logic ensuring admins cannot deactivate their own account or deactivate the last active administrator in the database.
3. **Lab 2 Test Suite Zero-Regression Policy**: Enforced that all 26 existing Lab 1 and Lab 2 tests continue passing 100% alongside 56 Lab 3 server API tests.
